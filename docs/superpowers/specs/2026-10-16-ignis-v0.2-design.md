## 0. 一句话

Ignis v0.2 是在 v0.1 已有的「能跑、能记、能调度」基础上，把终端交互与持久化补成的版本：一个**流式渲染清楚、输入顺手、会话记得住、上下文看得见**的个人 Agent CLI——主题 *Interactive & Persistent*。

## 1. 意图与为什么

作者（唯一用户与维护者）对 v0.2.0 的原话是「**日常拿它做 Agent 能做的事情**」。v0.1 已经证明 Ignis 能启动、能交互、能调用模型、能记忆与调度（README 与 `harness/` 有真机证据）；v0.2 的重点不是继续堆功能，而是让作者**愿意每天打开它**。

现状与目标之间的差距（v0.1 实测暴露）：

- 模型返回的内联 `<think>…</think>` 会原样打进回答（`docs/spikes/2026-10-15-relay-streaming-toolcalls.md` 记录 MiniMax-M2 实测会下发该形状）；
- 回答文本原样透传（无 Markdown、无换行纪律），`● Finished` 结束行可能直接粘在回答最后一个字符后面（`Renderer::on_event` 只 `write_all`，不回补换行；`commands/mod.rs` 紧随其后 `println!` 结束行）；
- 每轮打印完整任务 UUID 与出入 token；工具行只有 `→ 摘要`，成功结果不落一行、没有耗时；
- 输入只有单行、无历史、无补全、无多行；斜杠命令只有 `/exit` `/help` `/kernel`，且未知 `/命令` 会被当成任务发给模型；
- 没有会话概念：跨轮上下文在进程内存里，退出即丢；`ignis` 重开无法续聊；
- 上下文增长不可见（banner 的 `Memory: off` 其实是「active 事实数为 0」的文案，而记忆能力本身已完整实现——见 §11）。

继续沿用 v0.1 的观众假设：这是作者面向公司同事的能力证明，代码与文档要**真、稳、讲得清**。v0.2 的分层叙事不变：`apps/cli`（界面）→ `packages/core`（状态、权限、记忆、技能、调度）→ `packages/runtime`（内核）→ `packages/storage`（持久化）。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标（v0.2 必须做到）

1. **渲染**：流式 Markdown 子集（代码块、标题、列表、引用、行内代码、粗体）；推理内容（`<think>` 与各内核的 thinking/reasoning）与正文**分通道**呈现；工具状态行（开始/完成/失败 + 耗时）；结束行收敛；三种输出模式（Minimal / Normal / Debug）；暗色/浅色主题与无色模式；启动屏版本号与记忆段修正。
2. **输入**：手写行编辑器（raw mode，termios 走已有 libc）——多行编辑（Ctrl+J / Alt+Enter）、历史导航（↑/↓，持久化）、Tab 补全、粘贴（bracketed paste）、中日韩宽度正确的光标与换行、Ctrl+C / Ctrl+D 语义与 v0.1 一致；终端不支持 raw mode 时回退到 v0.1 的行模式。
3. **命令**：本地处理的斜杠命令（分组见 §6.5），不消耗模型 token；未知 `/命令` 本地报错、不再发给模型。
4. **会话**：SQLite 持久化（sessions / session_messages / compactions）；`ignis -c` 恢复当前工作区最近一次会话；`/new`、`/sessions`、`/resume`；`tasks.session_id` 关联。
5. **上下文**：`/context` 展示真实用量与预算占用（真实值 vs 无数据，明确标注）；`/compact` 把较早会话摘要化（原始消息保留、可追溯）。
6. **可观察**：`/status`、`/tasks`；工具计时；取消/失败语义与退出码一致（中断绝不报成成功）；`skills_used` 持久化。
7. **记忆·技能收口**：`/memory`（映射既有核心能力）、`remember` 成功时一行确认、`/skills`（含 `reload`）、实验性 `/learn`（只生成经用户审核的草稿）。
8. **TUI Beta**：`ignis --tui` 固定输入区、滚动消息、状态行、会话选择器、主题切换；复用同一会话与事件层。
9. **稳定性与发布**：终端兼容（Ubuntu 终端、SSH、tmux、80 列、无色）、pty 集成测试、验收 harness 扩展、README 更新。

### 2.2 非目标（明确不做）

沿用作者规划并显式化：

- Telegram / IM 等消息入口（维持 v0.1 推迟结论）；
- 后台多 Agent 面板；
- 技能自动生成/自动部署/自我改进闭环（v0.3 主题，v0.2 只做 `/learn` 草稿）；
- 向量检索 / 知识图谱 / 记忆自动提炼；
- MCP / 插件层（维持 `docs/spikes` 与 v0.1 设计文档的推迟结论）；
- Web Dashboard、语音、多用户 / SaaS、Skill 商店；
- Windows 支持（维持 v0.1 限制）；
- 鼠标交互、任务运行中继续输入或打断重定向（作者规划明确：v0.2 采用单任务策略「等当前任务结束再提交」）；
- 与 codex / claude 自身 `--resume` 的会话共享（维持 v0.1 限制 #9：Ignis 用自己的 canonical 历史渲染 prompt）；
- 审批事件化（`approval.requested` 之类进事件流；理由见 §6.1）。

### 2.3 反目标（出现即视为失败）

- 安装不上、随便跑个任务就报错（v0.1 反目标继续有效）；
- 流式输出丢字、重字、布局错乱；推理标记原样漏进正文；
- 取消/失败被报成成功，或退出码与状态不一致；
- 会话恢复后历史缺失、错序、重复；
- 密钥 / token 进入任何输出、日志、报告（含 Debug 模式与 TUI）；
- 80 列、`NO_COLOR`、tmux / SSH 下崩溃或错乱；
- 破坏 v0.1 回归：现有 e2e（demo A/B/C、审批模式、上限、脱敏）必须全绿；
- TUI 出问题时经典 CLI 受影响（TUI 是附加入口，坏了可以不用）。

## 3. 约束与环境事实

- **技术栈**：Rust（edition 2024，MSRV 1.98），Cargo workspace 五成员不变（`apps/cli`、`packages/{core,runtime,gateway,storage}`）；单二进制 `ignis`；Linux / macOS。
- **依赖**：**v0.2 不新增外部 crate**（延续 v0.1 的仓库习惯）。渲染、Markdown、宽度表、行编辑器、TUI 全部手写；raw mode / `TIOCGWINSZ` 走已有 `libc`；宽度表按常用东亚宽字符区间手写近似（不做完整 Unicode 表）。若执行中确需新增依赖，先改本文档并评审，不得静默引入。
- **事件契约**：`RuntimeEvent` 的 serde 形状即任务 JSONL 格式（跨模块契约，`packages/runtime/src/lib.rs` 有快照测试锁形状）。本文档对它的扩展（§6.1）必须同步：快照测试更新 + 旧日志可解析（新字段 `#[serde(default)]`）+ `task show` 容忍。
- **仓库规则**（延续，写进每份计划）：注释与文档中文；CLI 用户可见文案与模型可见工具描述英文；工具结果与错误信息中文；Conventional Commits（英文 type/scope、中文正文）；每任务收口验证 `cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace` 全绿、零警告；测试 hermetic（`IGNIS_HOME` 指到临时目录，绝不碰真实 `~/.ignis`）；生产路径无 panic、错误对人话。
- **文档规则**：`demo.md` 冻结；README「已知偏差」继续维护；验收结果如实记录（SKIP 不得写成 PASS）。
- **环境事实（2026-10-16）**：本机 Ubuntu x86_64；Rust stable 1.98；MiniMax-M2 端点流式 + 工具调用真机可用（spike 已关闭风险 #1）；`notify-send` 可用；node v26 / npm 11 可用（e2e 夹具依赖）；uv 未安装（Demo B 真实演示前置，README 已注明）。tmux / SSH / 浅色终端为 P6 手动矩阵项，本机具备 tmux 即可开始验证（不具备时如实记录）。
- **版本号**：banner 自 P1 起取 `env!("CARGO_PKG_VERSION")`，不再硬编码；workspace 版本在 P6 发布准备时升到 `0.2.0`。测试断言动态值，不锁死字面量。

## 5. 系统总览

```
                  ┌─────────────────────────────────────────────────────────┐
  用户 ──────▶    │ apps/cli（bin: ignis）                                   │
                  │  ┌─ 渲染器 render/（markdown · 宽度 · 模式 · 主题）      │
                  │  ┌─ 输入编辑器 editor（raw mode · 历史 · 补全 · 多行）    │
                  │  ┌─ 命令系统 commands（14 个本地斜杠命令）                │
                  │  REPL · 子命令 · 审批 UI · daemon 模式入口 ·（P5）TUI    │
                  └───────────────┬─────────────────────────────────────────┘
                                  │ Session（会话 id / 历史 / 输出模式）
                  ┌───────────────▼─────────────────────────────────────────┐
  daemon 模式 ──▶ │ packages/core（ignis-core）                              │
                  │  task · memory · skills · tools · scheduler · security   │
                  │  （P3 起：session store 接线与 PromptStats 同批）         │
                  └──────┬───────────────────────┬──────────────────────────┘
                         │ Runtime trait          │ Storage
                  ┌──────▼────────────┐   ┌───────▼──────────┐
                  │ packages/runtime  │   │ packages/storage │
                  │ native / codex    │   │ rusqlite(bundled)│
                  │ / claude          │   │ ~/.ignis/        │
                  │ + think 分割器     │   │ + sessions 表    │
                  └───────────────────┘   └──────────────────┘
```

- **事件流**：内核产出 `RuntimeEvent`（P1 扩后含 `reasoning_delta` 与工具 `call_id`）→ `TaskRunner` 写 JSONL（整行脱敏）+ 转发 sink → 经典渲染器或 TUI 消费。CLI 只渲染，核心与内核不 `print`（维持 v0.1 边界）。
- **会话数据**：canonical 消息进 `session_messages`；任务/审批/调度行不变；工具细节在 `logs/{task_id}.jsonl`。
- **输入历史**：`~/.ignis/history`（纯文本，0600），与 SQLite 无关。
- **依赖方向不变**：`core → {runtime, storage}`；`gateway → core`；`cli → all`。

## 6. 模块设计

### 6.1 统一事件层（`RuntimeEvent` 扩展）

现有 5 个变体（`text_delta` / `tool_exec` / `tool_result` / `usage` / `done`）保持语义，扩展如下：

```rust
pub enum RuntimeEvent {
    TextDelta { text: String },
    // 新增：推理/思考内容（与正文分通道）
    ReasoningDelta { text: String },
    ToolExec {
        name: String,
        summary: String,
        args: serde_json::Value,
        #[serde(default)] call_id: String,      // 旧日志缺省空串
    },
    ToolResult {
        name: String,
        ok: bool,
        output: Option<String>,
        #[serde(default)] call_id: String,
    },
    Usage { input_tokens: u64, output_tokens: u64, estimated: bool },
    Done { status: RunStatus, summary: Option<String>, error: Option<String> },
}
```

- JSONL 新增行类型 `reasoning_delta`；`task show` 对新增变体渲染 `reasoning_delta <首行截断>`，对缺字段与坏行沿用既有容忍策略。
- 时长（工具耗时）**不进契约**：渲染器按 `call_id` 配对 `ToolExec→ToolResult` 自测耗时；同一 `call_id` 的配对保证各出现 ≤1 次（native 每调用一对；codex/claude 见 §6.2）。
- 明确**不加** `approval.requested`：审批仍是同步回调（core 在 `gateway`/REPL 内联提示），没有消费者需要它；TUI Beta 在输入区内联提示。将来若做异步审批面板再评估。
- 快照测试（`runtime_event_json_shape_is_locked`）同步扩展；`RunStatus::as_str` 契约字符串不动。

### 6.2 内核适配：推理分道与工具结果收口

- **native**：
  - `ChatChunk` 增 `reasoning: Option<String>`（兼容 `delta.reasoning_content` 一类字段），命中即出 `ReasoningDelta`；
  - 文本通道接 `ThinkSplitter`（新模块 `packages/runtime/src/think.rs`）：识别 `<think>` / `<thinking>` / `</think>` / `</thinking>` 成对标记，**跨 chunk 分片安全**（部分标记的暂存回退，含跨多字节 UTF-8 边界）；未闭合块在流结束时结转为推理输出（不吞文字）；
  - 正文进入 `TextDelta`，推理进入 `ReasoningDelta`，同轮允许交错；
  - **正文口径**：分割器输出同时喂事件流与 canonical 累积——`Done.summary`、回填给模型的 assistant 消息与 `TaskOutcome.final_text` **只含正文**（推理仅存在于 `reasoning_delta` 的 JSONL 行）；否则标记会经任务摘要、跨轮历史与（P3 的）会话持久化继续流传。
- **codex**：`reasoning` / `agent_reasoning` 条目 → `ReasoningDelta`（当前被静默跳过）；`item.started` 的 `command_execution` → `ToolExec{call_id=item.id}`；`item.completed` 的 `command_execution` → `ToolResult{ok: exit_code==0 且 status=="completed", output=aggregated_output, call_id}`；`item.updated` 跳过（避免同一 `call_id` 重复出 `ToolExec`，保持「各 ≤1 次」的配对承诺；若某版本只发 `updated`，工具行只在完成时出现——记为已知限制）。
- **claude**：`thinking` 内容块 → `ReasoningDelta`（当前被跳过）；`tool_use` → `ToolExec{call_id=块 id}`；`type:"user"` 行里的 `tool_result` → `ToolResult{ok=!is_error, output=content, call_id=tool_use_id}`（当前被跳过）。
- 能力声明不变（codex/claude 仍 `usage:false` 等）；未知条目继续静默跳过（宽容原则）。
- 已知限制：模型若把标签当字面内容输出（如代码引文里的 `<think>`），会被判为推理通道——标签名保留给分道语义。

### 6.3 CLI 渲染器（`apps/cli/src/render/`）

拆为三个聚焦文件：`width.rs`（显示宽度与换行）、`markdown.rs`（行级/行内转换）、`mod.rs`（Renderer、模式、主题、事件消费、footer）。

**结构**：`Renderer { out, options, state }`，`options = { mode: OutputMode, color: bool, theme: Theme }`；`on_event(&RuntimeEvent)` 逐事件渲染；`finish()` 在任务收束时调用——冲刷挂起行、**保证换行**（修复结束行粘连），返回本轮的统计（工具数等）。

**流式纪律**（验收核心）：

- 普通文本逐字符即时输出（不做整行缓冲）；行首最多暂存 4 个字符用于判别块标记（围栏 / 标题 / 列表 / 引用）；
- 行内标记（`` ` ``、`**`）按「行内解析、行末结算」处理：遇到标记起点后暂存该片段，直到配对成功（转换为样式段）或本行结束（按字面输出——不吞字符、不改写）；长的 `**粗体**` 因此正常工作，未配对标记在行末原样回吐；
- 属性测试：同一内容按随机分片喂入，输出逐字节等于整体喂入（100 次随机切分 + 逐字符 + 跨 UTF-8 边界）；
- 代码块内不做行内转换；未闭合代码围栏在流结束时按已进入处理（不回吐标记）；
- **写入者纪律**：工具行 / 结束行 / `finish()` 一律从列 0 开始（先终结挂起的文本行）；命令层在同一任务内交错消费事件（不另起渲染任务）以压低写序竞态；审批提示仍是审批层的直接 stdout 写入，异步管线下的硬写序做不到——记为限制，P2/P5 单一写者时收口。

**Markdown 子集**（决策 #12）：围栏代码块（dim 呈现）、`#`–`####` 标题（去标记、加粗/亮色）、无序列表（`-`/`*`，续行缩进对齐）、引用（`> ` → 前缀条）、分隔线、行内 `` `code` ``、`**粗体**`。表格/链接/图片/斜体原样通过。

**宽度与换行**（决策 #13）：东亚宽字符按 2 列；**仅当 stdout 是 tty 时折行**——宽度取 `TIOCGWINSZ`（每轮任务开始时探测，失败或为 0 回退 80 列）；非 tty（管道、脚本、e2e）不插入物理换行，保持每行可 grep；前缀类块（引用/列表/代码）续行保持对齐；无空白超长串强断；ANSI 转义不计宽。TUI（P5）复用同一模块、宽度由面板给出。

**推理呈现**：

- normal：dim 流式输出（首次出现给一次 `· ` 前缀标记），与正文同屏但通道分明；
- minimal：不显示推理体，仅在其结束时打一行 dim 摘要（如 `· thinking (1.2k chars)`）；
- debug：`[reasoning]` 行标 + dim 原文。

**工具行**（按 `call_id` 配对）：

- normal：开始 `→ {summary}`（dim）；成功 `  ✓ {summary} · 0.3s`；失败 `  ✗ {首行 ≤200 字符}`（红）；无配对的 `ToolExec` 不预测结果；
- minimal：不逐行展示（footer 计数）；
- debug：附 `call_id` 与结果首行；
- `remember` 元工具成功时固定追加一行确认：`  ✓ memory: {key} ({scope}) {文本截断}`（决策 #22）。

**结束行**（`format_task_end` 重写，决策 #10）：

- normal：`● Done · 2.1s · 3 tools · task {短 id（13 字符）}`（非成功为 `● Failed|Aborted|Limit reached · …`，短 id 照常）；有 `skills_used` 追加 `· skills: a,b`；
- debug：追加 `tokens in=… out=… [(~)=估算] · task {full-id}`；
- minimal：`● Done · 2.1s`；
- 工具计数来自本轮 `ToolExec` 事件数（经 `TaskOutcome.tool_calls` 传递，见 §6.8）。

**banner**（`repl.rs`，决策 #11）：`IGNIS v{env!(CARGO_PKG_VERSION)}` / `● Ready` / `Workspace: …` / `Runtime: {kernel} · Skills: {n} · Memory: {n} facts` /（P3）`Session: …` / 未读告警行。

**颜色**（决策 #9）：`color=false` 时零 ANSI（测试断言不含 `\u{1b}`）；`ui.theme` 提供 dark/light 两套调色板（dim 在浅色下换 90 灰之类，构建者按对比度选择）；`NO_COLOR` 非空强制无色。

**Debug 安全**：debug 只渲染事件类型/摘要/首行（多为脱敏后内容），**不打印原始 args/output 全文**；要看全文用 `ignis task show`（JSONL 已整行脱敏）。

### 6.4 输入编辑器（`apps/cli/src/editor/`）

- **进入条件**：stdin 是 tty 且交互模式。raw mode 用 `libc::termios`（ICANON/ECHO 关闭、VMIN=1）；所有退出路径（含 panic hook、SIGINT 处理）恢复 termios 与原屏幕状态；**raw mode 只在读取输入期间启用**——任务执行、审批提示与守护进程提问期间终端必须处于 canonical/echo 模式（否则基于 `read_until(b'\n')` 的审批读不到 Enter），编辑器在每次 `read_line` 进出 raw；进入失败（非 tty、termios 报错）→ 回退 v0.1 行模式并打一行 note，REPL 不因此退不出。
- **键位**（钉死）：

| 按键 | 行为 |
|---|---|
| Enter | 提交当前输入 |
| Ctrl+J / Alt+Enter | 插入换行（多行编辑） |
| ↑ / ↓ | 历史导航（编辑中的行可恢复） |
| ← / → | 光标移动（按字符） |
| Home / Ctrl+A、End / Ctrl+E | 行首 / 行尾 |
| Backspace / Delete | 删除；空行 Delete 或 Ctrl+D = 退出 |
| Ctrl+U | 清空当前输入 |
| Tab | 补全（见 §6.5）；唯一候选直接接受，多候选列出 |
| Ctrl+C | 空闲 = 退出；任务运行中 = 取消（现有语义） |
| Ctrl+D | 空输入 = 退出（EOF 语义） |

- **多行**：提交时保留内部换行（作为单条任务文本）；续行提示 `… `；粘贴（bracketed paste）期间 LF 不触发提交。
- **历史**：↑/↓ 导航 + 文件持久化（决策 #15），提交时追加、相邻去重、上限 1000。
- **补全**：行首命令名（带一行描述）+ `/kernel` 取值；唯一候选直接补全，多候选列出行、输入不变。
- **宽度/光标**：按显示宽度定位（复用 `width.rs`）；IME 与非法字节沿用 v0.1 的宽松解码（`input.rs` 的 `read_line_lossy` 口径不变）。
- **重绘**：单行/多行输入用 `\r` + 逐行重绘；只在内容变化时输出。
- 已知限制：组合字符簇（emoji ZWJ 等）按字符近似；不支持 bracketed paste 的终端上多行粘贴可能逐行提交（记录为限制）。

### 6.5 命令系统（`apps/cli/src/commands/` 的 REPL 侧）

全部本地处理、零模型 token；分组帮助照作者规划：

```
SESSION      /new  /sessions  /resume <id>
AGENT        /model  /status  /tasks  /skills
INTELLIGENCE /memory  /context  /compact
INTERFACE    /details [minimal|normal|debug]  /help
（与既有 /exit、/kernel 共存，共 14 个）
```

- 解析规则：首个词是命令名；未知 `/命令` → `Unknown command: /foo — /help lists commands`（本地，不发送；修复 v0.1 行为）；
- `/details` 无参显示当前模式，有参切换（回显一行）；
- `/status`：kernel / model / workspace / session（new 或短 id）/ 未读告警数 / 最近一轮用量；
- `/tasks [N]`：最近 N 条表（短 id、status、耗时、prompt 前 40 字符），提示 `ignis task show <id>`；
- `/memory` 映射 `list/search/add/edit/delete`（复用 core 的 MemoryStore 与既有 CLI 输出文案）；
- `/skills [reload]`：列表（名称/来源/描述）+ 重扫目录（决策 #23）；
- 会话类命令依赖 P3 的会话存储（P2 先落命令框架与非会话命令）；
- `/resume` 与 `task show` 一样接受唯一前缀（≥8 字符）。

### 6.6 会话与恢复（P3）

**DDL 草案**（迁移 004；现有迁移 `user_version`=3）：

```sql
CREATE TABLE sessions (
  id TEXT PRIMARY KEY, title TEXT NOT NULL, workspace TEXT NOT NULL,
  kernel TEXT NOT NULL, model TEXT,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE TABLE session_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL REFERENCES sessions(id),
  seq INTEGER NOT NULL, role TEXT NOT NULL, content TEXT NOT NULL,
  tool_call_id TEXT, tool_calls TEXT,
  created_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_session_messages_seq ON session_messages(session_id, seq);
CREATE INDEX idx_sessions_workspace ON sessions(workspace, updated_at DESC);
CREATE TABLE session_compactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL REFERENCES sessions(id),
  upto_seq INTEGER NOT NULL, summary TEXT NOT NULL, created_at INTEGER NOT NULL
);
ALTER TABLE tasks ADD COLUMN session_id TEXT;
ALTER TABLE tasks ADD COLUMN skills_used TEXT;
```

- **生命周期**：REPL 启动生成内存会话 id；**首个任务提交时**落 `sessions` 行（title = 首条用户消息前 40 字符，去换行）；每轮任务结束把该轮的 canonical 消息（user + assistant 最终答复）按 `seq` 追加，更新 `updated_at`；每轮任务把 `session_id` 与 `skills_used` 写进 `tasks` 行。空会话（没提交过任务）不落库。
- **密钥脱敏**：canonical 消息（含用户提示词）、会话标题与压缩摘要与其它落盘面同一口径——已知密钥在写入会话存储/展示面与送进内核之前替换为 `***`；恢复后的历史与内存视图同源（P3 终审修复轮固化）。
- **恢复**：`ignis -c` 查本工作区 `updated_at` 最新会话 → 载入有效历史（最近一次 compaction 摘要 + 其后消息）作为 REPL 历史；`/new` 开新会话；`/sessions` 列最近会话（短 id / 标题 / 消息数 / 更新时间）；`/resume <前缀>` 切换。
- **与内核**：会话不绑定内核；`/kernel` 切换后后续任务沿用同一 canonical 历史（v0.1 语义不变）；外置内核自身 `--resume` 仍不共享（限制保持）。
- **恢复完整性判据**（验收用）：恢复后有效历史与退出前的 canonical 历史**逐条相等**（角色、内容、顺序）；连续 10 次「发消息 → 退出 → `-c` 恢复 → 断言 + 继续发消息」全绿。

### 6.7 上下文与压缩（P3）

- `/context` 输出（示意，字段以实现文案为准）：

```
context · kernel native · model MiniMax-M2
history: 12 messages · 8,420 chars (budget 200,000 chars, 4%)
last turn usage: in=3,636 out=58 tokens (exact)
session usage: in=12,304 out=1,002 tokens
prompt: 3 facts · 3 skills listed
```

- 数据来源：当前 REPL 历史（字符数）+ 配置预算；上一轮 `TaskOutcome.usage`（`estimated=false` 标 exact）；外置内核无 Usage 事件 → `last turn usage: unavailable (kernel reports no usage)`，**不伪造估算值**（决策 #21）；`prompt` 行来自新增 `TaskOutcome` 统计（见 §6.8）。
- **v0.2 交付口径（P3 终审裁定）**：只展示最近一轮精确用量与字符预算，**不展示会话累计与百分比**；会话累计的数据已具备（`tasks.session_id` + token 列），留待后续版本；本节示例中的 `session usage:` 行与 `4%` 属目标形态而非 v0.2 验收项。
- `/compact`（决策 #20）：
  1. 有效历史 ≤2 轮 → 提示无需压缩；否则保留最近 2 轮，其余进入压缩段；
  2. 用 native 客户端（`config.model` + Ignis 凭据）发一次无工具摘要请求，system 提示要求保留：任务状态、用户决策、未完成事项、关键事实与文件路径；
  3. 结果落 `session_compactions`，有效历史重建为「一条 user 角色摘要消息（前缀 `[Earlier conversation summary]`）+ 保留段」；原始消息**不删除**；
  4. 回显 `compacted: N messages → summary (M chars)`；缺凭据/外置内核 → `error: /compact 需要 native 内核凭据（当前内核不提供摘要所需凭据）`；
  5. 执行中的 native 内核仍按既有 `trim_history`（字符预算丢最旧轮）兜底，二者不冲突。
- 自动压缩不做（作者规划只要求基础压缩；手动触发 + 可见）。

### 6.8 可观察性（P1 起持续；PromptStats 随 P3 落地）

### 6.10 TUI Beta（P5）

- 入口：`ignis --tui`（与 REPL 同装配，同一会话/事件层）。
- 布局：顶部状态行（版本/工作区/内核/会话）、消息滚动区、固定底部输入区（复用编辑器键位）、底部状态行（context 占用 / 最近用量 / 模式）。

## 10. 风险与开工即验证项

1. **手写行编辑器的真实终端行为**（tmux / SSH / IME / 粘贴）：缓解 = raw mode 不可用回退 + pty 用例 + P6 手动矩阵；不做组合字符簇级精度。
2. **流式 markdown 的标记解析边界**：行内标记「行内解析、行末结算」，不丢字符 / 不改写是硬约束；属性测试穷举切分（100 次随机 + 逐字符 + 跨 UTF-8 边界）。
3. **恢复完整性口径漂移**：以 §6.6 的「canonical 历史逐条相等」为唯一判据写入测试。
4. **`/compact` 依赖 native 凭据**：外置内核/缺凭据明确报错；限制写入 README。
5. **TUI 工作量最大、风险最高**：P5 可 Beta/延后，P1–P4 价值独立。
6. **零新依赖下的宽度/编辑器复杂度**：范围已钉小（近似宽度表、不做 bidi/组合簇）。
7. **事件契约变更的兼容**：新字段 `serde(default)`，快照测试同步，`task show` 容忍；旧 JSONL 可继续读取。
8. **e2e 断言与输出形态的耦合**：断言只锁关键行（状态词/工具计数），不锁整行格式；形式变更集中在一处更新（P1 Task 8）。
9. **审批提示与工具行的写序**：异步管线下只能尽力而为（列 0 纪律 + 命令层同任务消费压缩竞态窗口）；P2/P5 单一写者时收口为硬保证。

## 11. 与既有文档 / 作者规划的偏差说明

对作者规划方案的逐项校正（均为按仓库现实对齐，非范围削减）：

1. **技术栈**：规划设想 Python（Rich / prompt_toolkit / Textual）。实际为 Rust workspace，且规划自带兜底（「如果已有成熟的 CLI，则沿用现有语言，不要为了 UI 更换技术栈」）——不换栈；对应能力由手写模块承担（决策 #3）。
2. **Memory 1.5**：规划假设记忆未实现（`Memory: off`）。实际记忆已完整（facts + supersede + FTS5 trigram + 三作用域 + 注入 + CLI 管理 + Markdown 镜像）；`Memory: off` 只是「active 事实数为 0」的文案。v0.2 只做确认行、`/memory` 收口与文案修正，不重做记忆。
3. **统一事件层**：规划提出新建 `IgnisEvent` 契约。实际 `RuntimeEvent` 已是唯一的跨模块事件契约（JSONL 形状锁定）。v0.2 扩展它而非另起一层（决策 #4）；规划的 `approval.requested` 明确不加（§6.1）。
4. **命令数量**：规划「12 个命令」，其中 `/usage` 并入 `/context`；保留既有 `/exit` `/kernel`，最终 14 个（§6.5）。
5. **Token 显示**：规划「默认隐藏，提供 /usage」。落地为结束行默认不带 token 明细（debug 模式显示）、`/context` 展示真实用量与预算。
6. **ID 噪声**：完整 UUID 只在失败时以短前缀出现在结束行；debug 与 `/tasks` 提供完整信息；`task show` 支持前缀（决策 #10）。
7. **输入 token 增长**：不是 bug——同一会话多轮任务的输入 token 随历史自然累积；v0.2 用 `/context` 把增长来源显式化（历史字符数 + 预算占比 + 事实/技能注入计数）。
8. **TUI 与主题**：维持规划分级（P1 优先，TUI Beta 可延后）；主题只做 dark/light/无色（不做完整主题系统）。
9. **`/learn`**：维持「只生成经用户审核的草稿，不自动部署、不执行新生成内容」；完整的技能自动测试与演进留 v0.3（与规划一致）。
10. **结束行 id 形态**：v0.1 成功结束行也打印完整任务 id（`apps/cli/tests/demo_a.rs` 按 I2 断言）；v0.2 改为 13 字符短 id + `task show` 前缀解析（决策 #10），属有意变更，e2e 断言同步更新。
