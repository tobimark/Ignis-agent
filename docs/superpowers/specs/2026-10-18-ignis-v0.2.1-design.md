## 0. 一句话

Ignis v0.2.1 是在 v0.2.0「会交互、记得住」之上的一次**终端体验打磨**：给 Ignis 一个拿得出手的门面（火焰 Logo + 品牌色启动屏）、把斜杠命令从「背命令」变成「浮层里选」、把 `/model` 从「打印一行字」变成「可操作的选择器」，同时把推理显示与会话历史两处可靠性口径修准——主题 *Flame*。

## 1. 意图与为什么

作者对 v0.2.1 的原话是「**希望有精美的命令行图形**」。v0.2.0 已经把交互骨架补齐（流式渲染、行编辑器、15 个斜杠命令、持久会话、TUI Beta），但实测反馈（`0.2.1demo/021fangan.md` 第 1 行起）指出：终端交互仍≈传统 REPL，缺少现代 CLI 的辨识度与顺手感。差距具体是：

- 启动屏是 5 行纯文本、零颜色（`repl/mod.rs::banner_lines`），没有品牌识别度；
- 补全只支持「命令名 + `/kernel` 取值」，且多候选只能等 Tab 后打一屏列表（`editor/reader.rs` 的 `write_listing`），没有浮层、不能键盘选择、不会随输入实时过滤；
- `/model` 只回显一行文字（`model_lines`），没有可选择的模型列表——代码库中甚至不存在「可选模型」的任何数据源；
- **normal 模式默认把推理正文以 `· ` 前缀流式打进终端**（`Renderer::push_reasoning`），与最终回答混在一起（方案作者原话：「内部推理说明仍然直接显示」）；
- 会话历史存在一处真实性风险：不 `-c` 重开时模型收到的历史确实是空的、且没有任何提示；空回答会落成空 assistant 行；系统提示里完全没有当前日期——「我刚才问你……了吗」这类问题的失败面由此而来（详见 §6.8，来自三路代码侦察的结论）。

本次升级只动**交互层**（`apps/cli` 的 `brand/`、`render/`、`editor/`、`tui/`、`commands/`）与两处**可靠性修复**（渲染口径、任务/会话层）。不重写 Native Runtime、Memory、Skills、调度——延续方案 §六的忠告。

观众假设不变：这是作者面向公司同事的能力证明，代码与文档要**真、稳、讲得清**；视觉升级也不得牺牲「Ubuntu 默认终端 / SSH / tmux / 80 列 / 无色」下的可用性。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标（v0.2.1 必须做到）

1. **品牌启动屏**：火焰 Logo（半块字符 + 逐格真彩）编译进二进制；火焰橙 `#F78340` 品牌色；按终端宽度三段响应（Full ≥100 列 / Compact 60–99 / Minimal <60 或非交互）；颜色三级降级（真彩 → 256 色 → 基本色/无色）；首帧两段式绘制（品牌块立即出、状态行随后填充）；新增 `--no-banner`。
2. **斜杠命令浮层补全**：输入 `/` 弹出候选、随输入实时过滤、↑↓ 选择、Tab 填入、Enter 执行高亮、Esc 关闭留输入；经典 REPL 与 TUI 两个入口都做；命令名、`/help`、执行、补全继续共用同一张 `COMMANDS` 表，并补齐参数候选（`/kernel`、`/details`、`/memory`、`/model`）。
3. **可操作选择器**：`/model` 打开模型选择器——候选经 `GET {base_url}/models` 发现（超时/失败回退到「仅当前模型 + 警告」）；TUI 为可搜索列表（泛化现有 Sessions selector），经典 REPL 为行号 / 唯一子串选择；经典 REPL 的 `/sessions` 同形态。
4. **推理与正文分道收口**：normal 模式不再直接流式打印推理正文，改为折叠口径（tty 内联活动行 + 收尾摘要行）；debug 保留原始 `[reasoning]`；minimal 不变。
5. **会话一致性修复与回归**：空回答不入历史/库；系统提示增加当前日期；native 每轮请求前落一条 `request_sent`（消息数/字符数/截断轮数）到任务 JSONL；新增「送模消息数组」多轮回归测试（对照方案验收第 10 条）。
6. **发布收口**：workspace 版本升 `0.2.1`；README / `docs/acceptance.md` 更新；终端矩阵补新区宽/色阶档重跑，如实记录。

### 2.2 非目标（明确不做）

- **默认入口翻转**（`ignis` 默认进 TUI）与 `--classic` 开关：TUI 仍为 Beta（忙碌期丢输入、无 SIGTERM 处理等既有偏差不属本版范围），翻转默认是破坏性 UI 变更，留 v0.3.0（偏差记录见 §11）。
- 鼠标交互、任务运行中排队输入/打断重定向、TUI 脱 Beta 化（维持 v0.2 非目标）。
- iTerm2 / Kitty 图像协议直显 PNG（方案 §二提到的「后续」；本版只做字符画）。
- 新存储迁移：**不加迁移、不改 004 之后的 DDL**；`request_sent` 只进任务 JSONL。
- 新增外部 crate（延续零新依赖约束，见 §3）。
- 重写内核 / 记忆 / 技能；`/compact`、`/learn`、调度、审批语义不动（除 §6.8 点名的字面修复）。
- `/skills` 选择器（无「选中」语义，保持表格；见 §11 偏差 #5）。
- 可展开的思考摘要交互（经典 scrollback 无折叠交互；TUI 侧留待后续，见 §11 偏差 #6）。

### 2.3 反目标（出现即视为失败）

- 视觉升级破坏可用性：SSH / tmux / 80 列 / `NO_COLOR` / 非 tty / 哑终端下乱码、错位、崩溃；
- `NO_COLOR` 或 `ui.color=never` 时输出出现任何 SGR（v0.2 硬约束继续有效）；Minimal 及以上任意档位出现「半截 ANSI 序列」或颜色泄漏；
- 补全菜单导致输入丢失、重复提交、误执行（高亮≠输入时的执行行为必须可解释，见 §6.4 键位表）；菜单存在时输入历史 / 多行编辑回归；
- 推理文本重新漏进正文（正文通道、回填模型的 assistant 消息、会话库三处都不含推理——v0.2 既有口径不得回退）；
- 会话修复后出现新口径漂移：送模数组与 `session_messages` 不一致、空回答残留、日期行进入模型可见工具描述等；
- 启动变慢或首屏闪烁：品牌块绘制不得引入额外阻塞（首帧必须仍然在 DB 工作前出现）；
- 破坏 v0.2 回归：现有 e2e（demo A/B/C、审批模式、上限、脱敏、内核、守护进程、sessions、tui、pty）更新断言后必须全绿；
- 密钥 / token 进入补全候选、选择器、Logo 相关输出（模型发现响应只取 `id` 字段）。

## 3. 约束与环境事实

- **技术栈**：Rust（edition 2024，MSRV 1.98），Cargo workspace 五成员不变；单二进制 `ignis`；Linux / macOS。
- **依赖**：**不新增外部 crate**（延续 v0.1/v0.2 约束）。半块字符画、真彩 SGR、256 色量化、浮层菜单、选择器、单 ESC 消歧全部手写；颜色探测走环境变量；终端尺寸走既有 `libc` `TIOCGWINSZ`（本版新增高度探测）。
- **素材与生成**：Logo 素材复制到 `assets/`（新增目录，`ignis-flame-transparent.png` + `ignis-flame-square-512.png`，`0.2.1demo/` 原件不动）；半块字符画由一次性生成脚本 `tools/gen-flame-art.py`（新增目录；生成期脚本，不参与构建、不进 CI）从透明底 PNG 产出 `apps/cli/src/brand/flame.rs` 并入库——**运行时零解码、零文件 IO**。
- **事件契约**：`RuntimeEvent` 的 serde 形状即任务 JSONL 格式（快照测试锁形）。本版新增 `request_sent` 变体：新字段按既有惯例处理（旧日志可解析、`task show` 容忍）；快照测试同步扩展。
- **存储**：无新迁移；`session_messages` / `session_compactions` / `sessions` 语义不变（除 §6.8 的空回答不再落行）。
- **仓库规则**（延续）：注释与文档中文；CLI 用户可见文案与模型可见工具描述英文；工具结果与错误信息中文；Conventional Commits（英文 type/scope、中文正文）；每任务收口 `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace` 全绿；测试 hermetic（`IGNIS_HOME` 指临时目录）；生产路径无 panic、错误对人话。
- **文档规则**：`demo.md`、`0.2.1demo/` 冻结（只读素材源）；README「已知偏差」继续维护；验收 SKIP 不得写成 PASS。
- **环境事实（2026-10-18）**：本机 Ubuntu x86_64；Rust stable 1.98；tmux 可用；图形终端 / SSH 目标同 v0.2 记录（跑不了记 SKIP + 原因）；真彩终端取决于本机 `COLORTERM`（无则验证 256 档）。
- **版本号**：workspace `version = "0.2.1"`（P1 即升，banner 走 `env!("CARGO_PKG_VERSION")` 动态取值）；测试断言动态值，不锁字面量。

```
                                   │ Session（历史 / 模型覆盖 / 模型目录快照）
                   ┌───────────────▼─────────────────────────────────────────┐
   daemon 模式 ──▶ │ packages/core（ignis-core）                             │
                   │  task（日期行 · 空回答口径 · 送模统计事件）              │
                   │  memory · skills · tools · scheduler · security        │

                   ┌──────▼────────────┐   ┌───────▼──────────┐
                   │ packages/runtime  │   │ packages/storage │
                   │ native / codex    │   │ 无迁移（004 不变）│
                   │ / claude          │   │                  │
                   │ + list_models     │   └──────────────────┘
                   └───────────────────┘
```

- **品牌数据流**：`assets/*.png`（原件）→（一次性）`tools/gen-flame-art.py` → `apps/cli/src/brand/flame.rs`（编译期常量）→ `brand::banner(...)` 按宽度档与色阶合成启动块 → 经典 REPL 直接写 stdout / TUI 推入 scrollback。
- **补全数据流**：`COMMANDS`（静态）+ 会话共享模型目录 `Arc<RwLock<Vec<String>>>`（`/model` 发现时刷新）→ `slash::complete(buffer, ctx)` → 结构化候选 → 经典浮层 / TUI overlay 渲染 → 键位状态机（选择/填入/执行）。
- **推理数据流**：内核 `ReasoningDelta` → `Renderer::push_reasoning`（按新模式口径折叠）→ 经典内联改写或 TUI 收尾行；正文通道与回填模型的 assistant 消息不含推理（v0.2 口径不动）。
- **送模数据流**：`TaskRunner::execute` 组装历史 → native `drive` 每轮 `trim_history` 后发 `request_sent` → JSONL（整行脱敏）→ `task show` 可见。
- **依赖方向不变**：`core → {runtime, storage}`；`gateway → core`；`cli → all`。

## 6. 模块设计

### 6.1 品牌层（新 `apps/cli/src/brand/`）

**字模生成**：从 `assets/ignis-flame-transparent.png` 生成两档字符画，长宽比按图像实际（约 0.75）换算——**Full ≈ 20 列 × 13 行，Compact ≈ 12 列 × 8 行**（与方案的 20×14 / 12×9 略有出入，按实际比例微调；方案 §一「12×9」同属示意）。每格 = 上下两像素：

```rust
pub struct Cell { pub top: Option<[u8; 3]>, pub bottom: Option<[u8; 3]> }
// 渲染：两像素不透明 → '▀'（fg=上、bg=下）；仅上 → '▀' fg；仅下 → '▄' fg；全透明 → 空格
```

- alpha 阈值（起案 64，生成时目视微调）决定「不透明」；半透明边缘像素按原色取用（素材为透明底，边缘近似可接受，不引入背景合成假设）。
- 生成物为纯 `const` 数据（每档 < 3 KB），单测锁「行列数与素材比例一致」「非空像素占比在合理区间」。

**三段响应与布局**（`brand::banner(...)`，输入：版本、工作区、内核、skills/memory 计数、会话短 id、未读告警、宽度、色阶、主题）：

| 档位 | 条件 | 形态 |
|---|---|---|
| Full | 宽度 ≥100 | 20×13 火焰 + 右侧字标 `IGNIS v0.2.1`（品牌色）/ 标语 `Your Personal Autonomous Agent`（dim）+ 状态块（下） |
| Compact | 60–99 | 12×8 火焰 + 字标 + 状态块（去标语） |
| Minimal | <60、stdout 非 tty，或 `TERM` 缺失/空/`dumb` | 单行 `IGNIS v0.2.1`（哑终端下零 SGR，见下） |

- **状态块**保留既有 5 行语义（`● Ready` / `Workspace: …` / `Runtime: {kernel} · Skills: {n} · Memory: {n} facts` / `Session: new\|{短 id}` / 未读告警行），颜色：`●` 绿、键名 dim、值常规；未读告警行保持警示语义（黄）。
- **两段式首帧（经典 REPL）**：品牌块（火焰 + 字标 + 版本 + 标语，零 DB 依赖）**先打印**；再做 `Session::new` / 计数 / `-c` 恢复，然后打印状态块（`Workspace` 属状态块，跟随其后以保证 `-c` 的 Session 行正确）。非原生内核的 `kernel_note` 追加位置不变。TUI 单帧合成本就是即时的，无两段式需求。
- **分层（校正后的 TUI 口径）**：经典 REPL 输出「品牌块 + 状态块」；**TUI 只在 scrollback 首屏推品牌块**（火焰 + 字标 + 版本 + 标语），状态块（`● Ready` / `Workspace:` / `Runtime:` / `Session:`）不进 scrollback——顶部状态行已承载 version / workspace / kernel / session，重复反而制造噪声。既有锁定断言「TUI 不出现 `● Ready`」（`apps/cli/tests/tui.rs`，与 `tui::startup_lines` 只推 note 行的现状一致）**保持**；`startup_lines` 相关测试更新为「品牌块出现、状态行不出现」。TUI 顶部状态行的 `IGNIS v…` 段改品牌色（结构不变）。
- **哑终端保守规则**：`TERM` 缺失 / 空 / `dumb` 时启动屏恒 Minimal 且**品牌块零 SGR**（即使 `ui.color=always`）；其余输出的颜色策略维持既有 `resolve_color` 语义不变。
- **`--no-banner`**：经典抑制品牌块 + 状态块；TUI 抑制品牌块（`-c` / 内核提示 / 告警 note 行保留）。Minimal 档的那一行同样受抑制。

### 6.4 经典 REPL 浮层菜单（`apps/cli/src/editor/`）

- **菜单状态**（reader 持有）：`menu: Option<MenuState { items: Vec<Candidate>, cursor: usize, offset: usize }>`，每次缓冲变化（含 Backspace/删除）重算；仅在「光标位于首行且首词为命令位置（尚无空格）或受支持的首参位置」时出现；普通文本、第二行及之后、多行缓冲不出现。
- **绘制**：菜单块 + 输入块视为一个整体重绘单元——菜单行（≤8 行窗口，可滚动，行含 `▸`/空格标记与截断）+ 1 行 dim 键位提示（`↑↓ select · Tab complete · Enter run · Esc close`），其下是输入块；重绘沿用 `\r\x1b[J` + 光标重锚定逻辑，高度变化（开/关/翻页）时以锚点行数差修正光标。终端高度探测<所需行数或探测失败 → **回退现状**（不画浮层，Tab 打列表，`write_listing` 行为保留）。
- **键位（钉死，按菜单位置分列）**：

| 按键 | 命令位（首词=命令名） | 参数位（`/kernel `、`/details `、`/memory `、`/skills `、`/model ` 的首个取值 token） | 无菜单时 |
|---|---|---|---|
| ↑ / ↓ | 移动高亮（窗口滚动随动） | 移动高亮 | 历史导航（现状） |
| Tab | 填入高亮命令（`expects_args` 追加一个尾随空格），不执行 | 填入高亮取值 + 一个尾随空格，不执行 | 现状（唯一候选接受 / 多候选列表） |
| Enter | 提交 `/<高亮>`（`expects_args` 补尾随空格后提交；无参命令即执行） | **不作用于菜单**：按普通提交照发缓冲原样（`/model gpt-4`、`/kernel codex` 等手动路径语义完全不变） | 现状（普通提交） |
| Esc | 关闭菜单，保留缓冲 | 同左 | 忽略（无行为变化） |
| 其他输入 / Backspace | 收键给编辑器，缓冲变化后重算（可能关闭菜单） | 同左 | 现状 |

  写作不变式：**菜单只替用户在「命令位」执行命令；参数位只做填入，绝不改写 Enter 语义**（防误执行的验收面，§8 第 5 条）。参数位菜单只在首个取值 token 内出现（`/memory` 子命令之后的查询文本、以及任何第二参数都不出菜单）。

- **单 ESC 消歧**：经典 reader 收包后若本包恰为单 `ESC`，用 `poll(fd, POLLIN, 50ms)` 观察后续字节——无后继=Esc 键；有后继=按序列继续解码。慢速分包的 `Alt+Enter`（ESC 与 CR 间隔 >50ms）会先关菜单再提交，与 TUI 既有已知偏差同类，记入 README 偏差。
- **回退与降级**：`StdinReader`（哑终端/非 tty 行编辑不可用）路径无菜单；`NO_COLOR` 下菜单无颜色但有 `▸` 标记；80 列下菜单行按显示宽度截断（复用 `truncate_to_width`）。

### 6.8 会话一致性修复与回归（`packages/core` + `apps/cli`）

侦察结论（三路并行代码审查）指向的可执行问题与处置：

1. **空回答落库成空行**：`TaskRunner::execute` 在 `final_text` 为 `Some("")`/纯空白时仍追加 assistant 消息；会话侧同样落库。修复：判定为「无回答」——不入内存历史、不落 `session_messages`（`append_turn` 的 reply 传 `None`）；渲染器在成功但无正文时打一行 dim `(empty answer)`。
2. **模型没有时间锚**：`build_system_prompt` 无任何日期。修复：系统提示头部加 `Current date: YYYY-MM-DD (Weekday).`（本地时区 `chrono`，调用方注入便于测试；格式固定、英文）。
3. **送模数组不可观测**：请求体从不落盘，出问题时无法定位。修复：`RuntimeEvent::RequestSent { messages: usize, history_chars: usize, dropped_turns: usize }`——**native 内核每轮 HTTP 请求前**（`trim_history` 之后）发出一次；`task show` 渲染一行（如 `request_sent · 7 messages · 1,234 chars · 0 turns trimmed`）；JSONL 快照测试同步；外置内核不发（如实记录差异）。
4. **已知解释面（不改行为，写进文档/测试）**：不 `-c` 重开或 `/new` 后历史确实为空（模型据此答「没有」是正确行为）；`-c` 恢复「本工作区最近**更新**」会话而非「上次在用」；失败轮只落 user（下轮出现连续 user，属预期形状）。以上口径由回归测试锁死并在 README 偏差里说明；`/compact` 后旧内容只存在于摘要。
5. **回归测试清单**（断言「送模消息数组」，脚本化模型）：
   - 单进程三轮：`[u₁,a₁,u₂,a₂,u₃]` 逐条相等（新增，pty 或 in-process e2e）；
   - `/new` 后：仅 `[u]`，且库中新建会话行；
   - 失败/取消轮后：下轮数组含两个连续 `user`（预期形状被锁）；
   - 空回答轮后：数组中无空 `assistant`；
   - `-c`：恢复最近更新会话（含「两个会话时取 updated_at 更大者」用例）；
   - `/compact` 后：首条为摘要消息（既有 pty 用例保持）。
   - 落点：`apps/cli/tests/sessions.rs` 扩展 + `apps/cli/tests/pty.rs` 或新增 `history.rs`；「真实端点的会话一致性」不做自动化（与既有真机口径一致）。

## 8. 验收标准（方案 10 条第 1–10 项 + 本版自加）

## 10. 风险与开工即验证项

1. **经典浮层重绘**（最难项）：菜单+输入块的整体重绘、高度变化锚定、滚动区边界。缓解=高度探测失败即回退现状；pty 高度矩阵（24 / 12 / 8 行）先行验证；绘制逻辑单测化（帧序列快照）。
2. **单 ESC 消歧的时序**：`poll` 窗口取值影响 `Alt+Enter` 体验；缓解=50ms 起案 + pty 用慢速分包用例锁行为 + README 偏差记录。
3. **半块字模在不同字体/终端下的观感**：字形按字符渲染，字体缺 `▀`/`▄` 罕见但可能；缓解=Minimal 永远可用；素材比例与阈值以目视校准并记录。
4. **真彩探测启发式**（tmux/screen 内 `COLORTERM` 可能缺失）：误判只影响观感不影响功能；256 档作为稳定退路。
5. **TUI 捕获白名单改为形状白名单**：SGR 全放行、其余转义全拒——拒绝表（光标/清屏/OSC/畸形）与接受表（真彩/256/基本色/属性组合）都是硬闸；放宽的上限=「scrollback 文本可被任意上色」，不涉及光标与屏幕状态。
6. **会话修复的涟漪**：空回答不落行会改变既有 `session_messages` 计数断言与 `/sessions` 的 MESSAGES 列（计数来源不变，但含空回答的历史库会出现行数差）；更新断言时以「canonical 判据」为准（§6.8.5）。
7. **模型发现端点的多样性**（MiniMax 等兼容端点未必实现 `/models`）：四种失败态全部走「警告 + 仅当前模型 + 手动路径不变」，不允许阻断。
8. **推理折叠的行为变更**：习惯看推理的用户需要适应（debug 保留原文）；README 明确写清，e2e 断言按新口径集中更新一处。

## 11. 与 `0.2.1demo/021fangan.md` 的偏差说明

逐项校正（均为按仓库现实对齐，非范围削减）：

1. **技术栈**：方案设想 Python（Rich / prompt_toolkit / Textual）。实际为 Rust 零新依赖仓库——字符画、浮层、选择器手写；方案的交互设计（键位表、三段 Logo、选择器语义）逐条保留（决策 #2、#3）。
2. **默认入口**：方案建议「`ignis` 默认进入现代化 TUI，`--classic` 兼容旧终端」。本版不做——TUI 仍处 Beta（忙碌期丢输入、无 SIGTERM 处理等偏差未修），翻转默认对现有用户是破坏性变更；`--classic` 随翻转一起留 v0.3.0（决策 #4）。`ignis` 的首屏与交互体验由经典 REPL 的品牌化 + 浮层补全 + 选择器兑现。
3. **Logo 尺寸**：方案 12×9 / 20×14 为示意。按素材实际比例取 12×8 / 20×13（生成脚本产出为准）。
4. **阶段顺序**：沿用方案（Logo + 补全浮层为最高优先；选择器次之；完整 TUI 后续）。「完整 TUI」在方案中为阶段 4，本版对应落成 TUI 侧的品牌化 + 浮层 + 选择器，不做固定输入区的大改（现状已具备）。
5. **`/skills` 选择器**：方案列 `/model`、`/sessions`、`/skills` 三者；本版收窄为前两者——技能列表是查看型信息，无「选中」后的动作语义，保持表格（决策 #14）。
6. **「可展开的思考摘要」**：方案建议「默认折叠 + 可展开」。经典 scrollback 无折叠交互载体，落成「默认折叠一行 + debug 展开原文」；TUI 侧的可展开留后续（非目标 §2.2）。
7. **`--version`**：方案列入交互规范，v0.2 已存在（clap `#[command(version)]`），本版不动。
8. **「输入历史和多行编辑保持正常」**：方案作为验收项列出；v0.2 已交付，本版按回归项对待（§8 第 8 条）。
9. **可诊断性**：`request_sent` 事件（决策 #16）为本版自加——方案原文「检查模型实际收到的消息数组」在无观测面时只能靠复现；落成 JSONL 事件后 `task show` 即可核对。
