# Ignis v0.2 阶段三（P3）：会话与上下文 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 把「退出即丢上下文」的 REPL 变成**记得住、接得上、看得见**的会话：迁移 004 落 `sessions` / `session_messages` / `session_compactions` 与 `tasks.session_id` / `tasks.skills_used`；`ignis -c` 恢复本工作区最近一次会话；新增 `/new` `/sessions` `/resume <id>`；`/context` 展示真实的历史字符占用与预算；`/compact` 用 native 凭据把较早轮次摘要化（**原始消息一条不删**）；banner 与 `/status` 补会话行；P1 终审遗留的两处脱敏（`TaskOutcome.final_text` / `TaskOutcome.messages` 的 assistant 内容、`ApprovalRequest.args`）随本阶段收口。

**架构：** 三层落地，依赖方向不变（`cli → core → {runtime, storage}`）：

1. `packages/storage/src/sessions.rs`：迁移 004 的 DAO（会话行、消息行、压缩行、`tasks` 两个新列的读写）。
2. `ignis_core::session::SessionStore`：标题规则（首条用户消息、字符安全截到 40）、懒创建、轮次追加（`seq` 续写 + `updated_at` 刷新）、**有效历史重建**（最近一次 compaction 摘要 + 其后消息）、列表与前缀解析；`/compact` 的切分与摘要请求也在这里（无工具 native 请求）。
3. `apps/cli`：`Session` 成为会话状态的唯一持有者（`history` / `current_session` / `last_prompt_stats`），`run_task(prompt, kind)` 不再收历史参数；`slash` 增加 SESSION 分组与 `/context` `/compact`；REPL 只负责读行、分发与打印。

会话只存 **canonical 消息**（user 提示词 + assistant 最终答复，与 v0.1 的跨轮上下文同一口径）；工具细节继续只存在任务 JSONL；`ignis run` 与调度运行不绑会话（`tasks.session_id` 为 NULL）。

**技术栈：** Rust（edition 2024）；**零新增依赖**（会话 id 复用 core 已有的 `uuid::Uuid::now_v7`，与任务 id 同源；时间戳复用 `ignis_storage::now_millis`；表格/时间渲染复用 `commands::task::{render_table, format_time}`）。

**Spec：** `docs/superpowers/specs/2026-10-16-ignis-v0.2-design.md`（重点 §6.6 会话与恢复、§6.7 上下文与压缩、§6.8 可观测性、§6.5 命令分组、§4 决策 #18/#19/#20/#21、§7 的 P3 行与待定项、§8 验收 3/4、§10 风险 3/4/7/8）。本计划只覆盖 P3；`/skills reload` 与 `remember` 确认行（P4）、`/learn`（P4）、TUI（P5）、终端矩阵与 README（P6）**不实现、也不在 `/help` 里出现**。

## 全局约束

来自设计 §3 与控制器决策，适用于本计划所有任务：

- **零新增依赖**：不添加任何 crate（含 dev-dependencies）。会话 id 用 core 已有的 `uuid`，时间戳用 `ignis_storage::now_millis`，表格用 `commands::task::render_table`。
- **迁移只加不删**：004 只 `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE ADD COLUMN`；旧库（`user_version` 3）升级后既有 `tasks` / `approvals` / `facts` / `jobs` / `job_runs` / `alerts` 行一个字段都不变。`MIGRATIONS` 的条数从 3 变 4，随之 `db.rs` 里三条断言 `user_version == 3` 的用例改成 4。
- **语言**：代码注释与文档中文；**本期新增的 REPL 界面文案（分组帮助、`/new` `/sessions` `/resume` `/context` `/compact` 的回显与 `note:`/`error:` 文案）一律英文**；**复用**的既有文案保持原样（`/memory` 的中文回执、`/kernel` 的中文错误、`fallback_note`、`kernel_note`）。新增警告行沿用 P2 的先例用英文（`warning: session write failed: …`）；core 内部已有的中文警告（读记忆失败等）不动。
- **收口验证**：每个任务收口跑 `cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`，全绿、零警告。
- **测试 hermetic**：不碰真实 `~/.ignis`（单测传显式路径、pty 用例用临时 `IGNIS_HOME`）；不依赖网络与真实模型——需要模型往返的用例（`/compact`、`run_task` 的会话追加）一律把 config 的 `model.base_url` 指到 `ScriptedModel`。
- **生产路径无 panic、错误对人话**；会话与压缩路径不打印密钥。
- **提交**：Conventional Commits，英文 type/scope + 中文正文；一次提交一个可验证单元。
- **不 Delta 化既有语义**：退出码（0/1/130）、`RunStatus::as_str` 契约串、P1 渲染契约（`RendererOptions` 形状、`resolve_color`、`format_task_end`）、P2 编辑器与 `LineReader` trait **一行不改**。`ignis run` 仍是一锤子买卖：不建会话行、不传 `session_id`。
- **恢复判据只有一条**（设计 §6.6 / §10 风险 3）：恢复后的有效历史与退出前的 canonical 历史**逐条相等**（角色、内容、顺序），由 core 的 10 次启停用例与 Task 8 的 pty 用例分别钉住。
- **未知斜杠命令**仍本地报错、不送模型（P2 行为不变）；新增的五个命令（`/new` `/sessions` `/resume` `/context` `/compact`）各自在自己的任务里进 `COMMANDS`——不许提前列进 `/help`（提前列出来等于说谎，P2 已有先例）。

                                  pub created_at: i64 }
pub struct CompactionRecord { pub id: i64, pub session_id: String, pub upto_seq: i64,
                              pub summary: String, pub created_at: i64 }

impl Db {
    pub fn insert_session(&self, s: &NewSession) -> Result<()>;                       // created_at = updated_at = s.created_at
    pub fn get_session(&self, id: &str) -> Result<Option<SessionRecord>>;
    pub fn latest_session_for_workspace(&self, workspace: &str) -> Result<Option<SessionRecord>>; // updated_at DESC, id DESC

- **本阶段裁定/落定的口径（执行中如需改动，先改本计划再改代码）**：
  1. **失败/中止轮次写不写库**（设计 §7 的待定项）：按 v0.1 内存历史逐条对齐——**只追加 user 消息，不追加 assistant**（v0.1 的 `TaskOutcome.messages` 只在成功时带最终答复），恢复判据因此对两种轮次都成立。
  2. **`history_chars` 与 `/context` 的 `{n}` 不是同一快照**：`chars` 来自最近一次组装（含本轮输入、pre-kernel-trim），`n` 是当前有效历史条数；`context_lines` 的文档注释明说这一点，测试分别钉住。设计示例里的 `, 4%` 按控制器钉死的行文案**不输出**（预算区间只给绝对值）。
  3. **标题规则**：`\r` / `\n` 各换成空格 → trim → 按字符截到 40（不加省略号，保证 `/sessions` 的「≤40 字符」不变量）；截断后为空给 `untitled`。
  4. **`/compact` 的「无轮可压」是普通回显不是错误**（`compact: nothing to compact`，stdout）；两条真错误（无凭据、无会话）走 `Err`，由 REPL 统一加 `error: ` 前缀。
  5. **`tasks.skills_used` 用独立 DAO 方法在 `finish_task` 之前写**：P1 钉死的 `finish_task` 九参签名与十来个调用点一行不动；`tasks.session_id` 则在 `insert_task` 时写（行创建即关联，不留「有任务无会话」的中间态）。
  6. **`PromptStats.facts_injected` 计的是交给 prompt 装配的事实条数**（预算截断发生在 `prompts` 内部，不回调）；极端超预算时它可能略大于实际渲染行数，属已知近似。
  7. **`/new` 与 `/resume` 只清会话状态**：`history`、`current_session`、`last_usage`、`last_prompt_stats`；输出模式、模型覆盖、内核切换一律不动。
  8. **`/context` 对外置内核固定写 `unavailable`**（控制器钉死），与 `/status` 的「有 Usage 就显示」略有出入：外置内核实际上不上报 Usage，这个不对称只有伪造用法事件的内核才会碰到。
  9. **`session_messages.tool_call_id` / `tool_calls` 在 P3 一律 NULL**：canonical 消息是纯文本，工具细节留在任务 JSONL；列先按设计 §6.6 的 DDL 建好，将来要存工具轮次时不用再迁移。
  10. **新警告行用英文**（`warning: session write failed: …`，与 P2 编辑器的英文 warning 同一先例），复用的中文文案（`/memory` 回执、`/kernel` 错误、core 的读记忆警告）一个字节不改。
