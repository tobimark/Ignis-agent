# Ignis v0.2 阶段五（P5）：TUI Beta 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 交付 `ignis --tui` 这个**附加入口**的全屏界面（Beta）：备用屏 + 固定输入区（复用 P2 的编辑器状态机与键位）+ 有界滚动区（上限 2000 行）+ 顶部/底部状态行 + 内联审批（`[a]s[r]d`）+ `/learn` 内联确认 + `/sessions` 全屏选择器；与经典 REPL 共用同一个会话、事件层、渲染器与命令系统，**不复制第二套 Markdown/宽度/编辑实现**；任何一处进不去（非 tty、`TERM=dumb`、termios/备用屏失败、终端小于 20×8）都打一行 note 并原样跑经典 REPL。

**架构：** 三块落地，依赖方向不变（`cli → core → {runtime, storage}`）：

1. **终端层（新模块 `apps/cli/src/tui/`）**：`term.rs` 管备用屏/光标/尺寸/panic hook（raw mode 复用 `editor::raw::RawMode`，`ISIG` 保持开着）；`capture.rs` 把一个 `Arc<Mutex<Vec<u8>>>` 的 `Write` 适配器交给**既有渲染器**（`Renderer::new` 的 `out` 已可注入），并把捕获字节净化成只能「显示、不能驱动终端」的文本；`view.rs` 是纯帧合成器 + 有界滚动区；`input.rs`/`app.rs` 是输入路由与主循环；`approval.rs`/`confirm.rs` 是两条通道式接缝。
2. **会话层接缝（`apps/cli/src/commands/`）**：`Session::run_task_with_out`（单一写入面，经典 `run_task` 走 `stdout`/`stderr` 两个面，行为逐字不变）、`Session::new_with_handler`（注入审批处理器）、`Session::learn_with`（注入确认面）、`Session::ui_config`（TUI 的颜色/主题来源）；`approval::prompt_lines` 与 `commands::learn::{preview_lines, draft_header}` 成为两处共用的**唯一**文案来源。
3. **入口（`cli.rs` + `repl.rs`）**：全局 `--tui` 旗标 + 与 `-c` 同形的守卫；`repl::run` 先试 TUI，不可用时打 note 落回**原封不动**的经典路径。

**关键约束（借用冲突与死锁的规避，全部任务共享）：** 任务/`/compact`/`/learn` 的 future 借用 `&mut Session`，因此忙碌期**一律不碰会话**——帧里的会话事实来自启动任务前取好的 `ViewFacts` 快照；审批/确认请求与那个 future 是**同一个 `tokio::select!` 的分支**（UI 循环绝不会「等 UI 处理而 UI 自己正 await」）。忙碌期不接受编辑器输入（单任务策略，设计决策 #25）。

**技术栈：** Rust（edition 2024）；**零新增依赖**（`libc` 的 termios/`TIOCGWINSZ`/`TIOCSWINSZ`、`tokio` 的 `signal`/`time`/`sync` 都已在 workspace 依赖里；不引 `futures`——确认面的 `BoxFuture` 用 std 的 `Pin<Box<dyn Future…>>` 拼法）。

**Spec：** `docs/superpowers/specs/2026-10-16-ignis-v0.2-design.md`（重点 §6.10 TUI Beta、§6.3/§6.4 渲染器与编辑器复用、§6.5 命令分组、§6.6/§6.7 会话与上下文、§7 的 P5 行、§2.2/§2.3 非目标与反目标、§10 风险 5）。本计划只覆盖 P5；**终端兼容矩阵（SSH/tmux/无色真机）、README 已知偏差与版本号 0.2.0（P6）不实现**；P5 不新增任何斜杠命令、不改 `/help` 的 15 条。

## 全局约束

来自设计 §3 与控制器决策，适用于本计划所有任务：

- **零新增依赖**：不添加任何 crate（含 dev-dependencies）。宽度/帧合成/净化/选择器全部手写；terminal 进出走已有 `libc`；信号与定时走已有 `tokio`（`signal`、`time` 已在 feature 列表里）。
- **语言**：代码注释与文档中文；**本期新增的界面文案一律英文**；**复用**的既有文案一个字节不改（`Approval required` 四行与 `choice> `、`draft skill …`、`save this skill draft? [s]ave [d]iscard> `、`Unknown command: …`、`● Done/● Aborted…` 结束行、`error: …`、`note: no previous session…`、`⚠ {n} unread alerts — run \`ignis alerts\``、`INVALID_WARNING`、`fallback_note` 两个先例）。TUI 的 chrome（状态行、输入区提示）是新文案，英文。
- **不 Delta 既有契约**：`RuntimeEvent` 形状、`Renderer`/`RendererOptions`/`palette`/`resolve_color`/`format_task_end`/`width::wrap`、`editor::keys` 的既有解码表（只**新增** `take_lone_escape`）、`editor::state`/`draw::CONTINUATION`、`slash` 的 `COMMANDS` 与全部渲染函数、`approval::format_prompt` 的字节、`Session` 既有方法与 `run` 的行为、`PtyOptions` 的既有字段语义、既有 pty/e2e 断言、`/help` 的 15 条与分组顺序——一行不改。
- **经典 REPL 的字节级不变**：`run_task` 仍然把渲染与结束行写 stdout、把 `error:`/`warning:` 行写 stderr；`repl::run` 在 TUI 不可用时走的还是原来那条路径（banner、`-c` note、读取层回退 note 一字不改）。
- **TUI 坏不影响经典 CLI（反目标）**：TUI 的失败只在 `repl::run` 里收成一行 note + 落回经典路径；`--tui` 与任何子命令同用是用法错误（`error: --tui only applies to the interactive REPL`，退出码 1，与 `-c` 的守卫同一形状）。
- **模型输出不能驱动终端控制（反目标）**：经捕获缓冲进滚动区的字节只放行渲染器自己的 SGR 白名单（`\x1b[0m/1m/2m/31m/36m/90m`）、`\n`、`\t`，其余 ESC/CSI/OSC 与控制字节一律丢掉；屏幕框架自己写的序列（清行、定位、备用屏）只由 `view::compose`/`term` 产生。
- **Beta 边界（决策 #11）**：不做鼠标；滚动区有界（2000 行）；任务运行中不接受输入、不做打断重定向；主题只用 dark/light（`render::palette`），无色时零 SGR；不新增只属于 TUI 的命令。
- **生产路径无 panic**：锁中毒取回内部值、ioctl/写失败按 fail-soft 收束、帧合成对任意尺寸都是全函数（不 panic、不越界）；唯一允许的「异常路径」是 panic hook 的终端还原（它本身也不 panic）。
- **测试 hermetic**：不碰真实 `~/.ignis`（单测用 `session_fixture`/临时目录，pty 用例用临时 `IGNIS_HOME`）；不依赖网络（需要模型往返的用例把 `model.base_url` 指到 `ScriptedModel`）；pty 用例本机 Linux 跑，macOS 走同一份配方。
- **dead_code 与可见性**：本阶段每个任务都要过 `-D warnings`。新模块的入口一律 **`pub`**（`render/width.rs` 的先例：`pub(crate)` 而暂时没有消费者的条目会被 dead_code 判成警告，TUI 的分层让「先落地、后接线」成为必然）。
- **收口验证**：每个任务收口跑 `cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`，全绿、零警告。
- **提交**：Conventional Commits，英文 type/scope + 中文正文；一次提交一个可验证单元。

## Review Focus

以下五类情形设计文档未逐条展开、但真实用户会撞上；每条都已绑定到具体任务的测试，执行者必须让这些测试存在且通过：

1. **终端还原的每一条退出路径**：`/exit`、空输入 Ctrl+D、空闲 Ctrl+C、EOF（对端关闭）、任务中途 Ctrl+C、panic——每条都必须还原备用屏、光标与 termios；漏一条用户就会回到「没回显、屏幕还是备用屏」的 shell。测试在 Task 1（`guard_enters_and_leaves_the_alt_screen_on_a_pty`：进入字节与 `Drop` 字节逐字 + termios 复原）与 Task 7（pty：`/exit` 后 `\x1b[?1049l` 出现且 `echo_and_canonical() == (true, true)`）。
2. **模型输出驱动的终端控制**：捕获字节里放行的必须只有渲染器自己的 SGR 白名单；清屏、备用屏切换、光标定位、OSC 标题这类序列一律丢掉——否则一条回答就能把界面打花或改窗口标题。测试在 Task 1（`sanitize_keeps_the_renderer_palette_and_drops_every_other_escape`：`\x1b[2J`、`\x1b]0;x\x07`、`\x1b[?1049l`、裸 ESC、`\x08`、`\x00` 全丢；六个白名单 SGR 逐字保留）与 Task 3（摄入路径只经这一个函数）。
3. **帧的边界与退化尺寸**：帧恒好 `rows` 行、每行显示宽度 ≤ `cols`、宽字符不被切半格、`rows < 5` 或 `cols` 极小时不 panic 也不越界写——终端比预期小是常态（用户随手拉窗口）。测试在 Task 2（`compose_is_total_at_any_size`（1×1…6×9）、`compose_truncates_to_the_width_and_never_emits_a_longer_line`、`truncate_to_width_never_splits_a_wide_char_or_counts_ansi`）与 Task 1（截断辅助函数本身）。
4. **借不到会话导致的借用冲突/死锁**：future 借用 `&mut Session` 期间绝不碰会话；审批/确认的请求必须与那个 future 在同一 `select!` 里推进，否则「UI 等 UI」当场死锁（用户按什么键都没反应）。测试在 Task 3（`drive_drains_the_capture_and_redraws_while_the_task_runs`：pty 后备的守卫 + 只让出一次的控制 future）与 Task 4/Task 5（`approval_keys_reply_to_the_pending_request`、`tui_confirm_replies_only_on_s`：请求到达 → 输入态切换 → 回信，全部在驱动同一次 `select!` 里）。
5. **降级路径与经典 CLI 的隔离**：`--tui` 的任何失败都只给一行 note 并跑经典 REPL；`--tui` 与子命令同用是用法错误（退出码 1）；经典路径的字节与既有断言一条不动；非 native（codex/claude）在 TUI 里照跑。测试在 Task 6（`tui_flag_only_applies_to_the_repl`、`tui_unavailable_reason` 的表、`resume_continue`）与 Task 7（TERM=dumb 与过小终端的降级 pty 用例 + 全量回归）。

// apps/cli/src/tui/mod.rs
/// 终端尺寸（列 × 行）。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Size { pub cols: usize, pub rows: usize }

/// TUI 可用的最小终端：小于它就降级经典 REPL（设计 §6.10「尺寸过小」）。
pub const MIN_COLS: usize = 20;
pub const MIN_ROWS: usize = 8;

/// 进不去 TUI 的理由（`None` = 可用）。纯函数：tty/TERM/尺寸三件事都由调用方探好后传进来，
/// 用例不必造终端也不必改环境变量。
pub fn tui_unavailable_reason(
    stdin_tty: bool, stdout_tty: bool, term: Option<&std::ffi::OsStr>, size: Option<Size>,
) -> Option<String>;

/// 降级时的一行 note（逐字，英文 chrome；`reason` 来自 [`tui_unavailable_reason`] 或守卫的 io 错误）。
pub fn fallback_note(reason: &str) -> String;   // "note: TUI unavailable ({reason}); falling back to the classic REPL"

// apps/cli/src/tui/term.rs
/// 备用屏进入/退出、光标隐藏/显示与清屏的字节（逐字钉住；帧协议只由这里与 `view::compose` 产生）。
pub const ENTER_ALT_SCREEN: &str = "\x1b[?1049h";
pub const LEAVE_ALT_SCREEN: &str = "\x1b[?1049l";
pub const HIDE_CURSOR: &str = "\x1b[?25l";
pub const SHOW_CURSOR: &str = "\x1b[?25h";
pub const CLEAR_SCREEN: &str = "\x1b[2J";
pub const CURSOR_HOME: &str = "\x1b[H";

/// 全屏终端守卫：进入时写 `ENTER_ALT_SCREEN + HIDE_CURSOR + CLEAR_SCREEN + CURSOR_HOME` 并进 raw
/// mode；`Drop` 写 `SHOW_CURSOR + LEAVE_ALT_SCREEN` 并析构 raw 守卫（termios 复原 + 关 bracketed
/// paste）。**每一条退出路径**（含 panic 展开与早退）都靠它收尾。
pub struct TerminalGuard { /* raw: RawMode, out: Box<dyn Write + Send>, size: Size */ }
impl TerminalGuard {
    /// 生产入口：stdout + `STDOUT_FILENO` + `RawMode::enable_on`。
    pub fn enter() -> io::Result<(TerminalGuard, Size)>;
    /// 注入入口（用例在 pty 从端上跑同一条路径）：`fd` 同时用于 raw mode 与尺寸探测。
    pub fn enter_with(
        out: Box<dyn Write + Send>, fd: i32, enable: impl FnOnce(i32) -> io::Result<RawMode>,
    ) -> io::Result<(TerminalGuard, Size)>;
    /// 写一段字节（帧、note）并 flush；失败由调用方忽略（EPIPE 等）。
    pub fn write(&mut self, bytes: &[u8]) -> io::Result<()>;
    /// 缓存的尺寸（进入时探一次）。
    pub fn size(&self) -> Size;
    /// 重新探测（SIGWINCH）；探测失败保留旧值。
    pub fn refresh_size(&mut self) -> Size;
}

/// `TIOCGWINSZ` 探测；非 tty / ioctl 失败 / 报 0 给 `None`（调用方回退 80×24）。
pub fn probe_size(fd: i32) -> Option<Size>;

/// 安装 panic hook（进程内一次）：先按 `ACTIVE` 现场与备用屏退出序列做 best-effort 还原，再转交
/// 原来的 hook。TUI 启动时调用一次，重复调用是 no-op。
pub fn install_panic_hook();

// apps/cli/src/tui/capture.rs
/// 渲染器的输出落点：把字节追加进共享缓冲；`flush` 是 no-op（渲染器每个事件自己 flush）。
pub struct CaptureSink(Arc<Mutex<Vec<u8>>>);
impl CaptureSink {
    pub fn new(buffer: Arc<Mutex<Vec<u8>>>) -> Self;
    /// 建一对：`(sink, buffer)`。
    pub fn pair() -> (Self, Arc<Mutex<Vec<u8>>>);
}
impl Write for CaptureSink { /* write / flush */ }

/// 排空共享缓冲（`std::mem::take`）；锁中毒取回内部值，不 panic。
pub fn drain(buffer: &Arc<Mutex<Vec<u8>>>) -> Vec<u8>;

/// 捕获字节 → 可进滚动区的文本：只放行渲染器自己的 SGR 白名单（`\x1b[0m`/`\x1b[1m`/`\x1b[2m`/
/// `\x1b[31m`/`\x1b[36m`/`\x1b[90m`）、`\n` 与 `\t`；其余 ESC（连同它后面的 CSI/OSC 序列）与
/// C0/DEL 控制字节一律丢掉；非法 UTF-8 按替换字符顶上（防御性，渲染器本体只写合法 UTF-8）。
pub fn sanitize(bytes: &[u8]) -> String;

// apps/cli/src/render/width.rs（新增）
/// 按**显示宽度**截断：返回最长的、显示宽度 ≤ `width` 的前缀。ANSI 转义序列（`\x1b[` … 终结
/// 字节）不计宽且原样保留在结果里；宽字符不会被切开（宁少一列，不多占一列）。
pub fn truncate_to_width(text: &str, width: usize) -> &str;

// apps/cli/src/editor/keys.rs（新增方法；既有解码表不动）
impl Decoder {
    /// 吃掉「一个孤零零的 ESC」并报 true（其余情况返回 false 且不动缓存）。TUI 每 tick 调它，
    /// 把用户按的 Esc 从「可能是半条转义序列」里解救出来；经典编辑器不调它，行为零变化。
    pub fn take_lone_escape(&mut self) -> bool;
}

- **本阶段裁定/落定的口径（执行中如需改动，先改本计划再改代码）**：
  1. **输入区只有 3 行，装不下经典的 5 行审批提示**：审批的 4 行正文（`prompt_lines`）进滚动区，输入区第 1 行放 `choice> `（与经典提示词的最后一段逐字一致）。文案仍是**同一份**（`format_prompt` 由 `prompt_lines` 拼出，字节不变）。
  2. **`BoxFuture` 不引 `futures`**：`apps/cli` 没有 `futures` 依赖，确认面的未来类型用 std 拼成 `ConfirmLearn = Pin<Box<dyn Future<Output = bool> + Send + 'static>>`（与 `BoxFuture<'static, bool>` 同一类型，零新增依赖）。闭包 `'static` 的代价是名字要从草稿里先取出来（`confirm_save_owned`）。
  3. **Ctrl+C 的取消归属**：任务轮次的取消令牌仍在 `run_task_with_out` 内部（经典语义一字不改，SIGINT 由它自己的 watcher 收）；TUI 的 SIGINT 分支只决定「忙碌 → 留在界内 / 空闲 → 还原终端并以 0 退出」。`/compact` 与 `/learn` 的令牌由 TUI 持有（它们的签名本来就收令牌），SIGINT/审批拒绝时显式取消。
  4. **Esc 需要消歧窗口**：字节解码器是无时钟的（半条转义序列必须留在缓存里），所以选择器的 Esc 由 100ms tick 上的 `Decoder::take_lone_escape()` 落地；这个窗口也是已知限制之一（Alt+Enter 被切在两 tick 之间可能退化成 Enter）。
  5. **经典 stdin/stderr 的拆分 vs TUI 的单一捕获面**：`run_task_with_out` 用 `shared_writer` 把一个面拆成两份给渲染面与错误面，经典 `run_task` 仍传 stdout/stderr 两个真实面（字节不变）。
  6. **自拉起在 TUI 里不问答**：`daemon::autostart_with(..., interactive = false, out, err)`——TUI 里 `stdin` 是 tty 但被 raw mode 占着，问答会与界面打架；提示行照打（进捕获缓冲），经典路径的行为一字不改。
  7. **帧里没有 SGR 不等于没有转义**：`color=false` 指零 **SGR**（颜色/亮度），光标定位与清行（`\x1b[H`、`\x1b[K`、`\x1b[?25l/h`、备用屏）是画屏必需，不算颜色；`compose` 每行结尾补 `\x1b[0m`（仅 `color=true`）以免被截断的行把颜色漏到下一行。
  8. **非 tty 的降级只有单测**：pty 夹具三个 stdio 都是同一个从端，造不出「stdout 不是 tty」的进程；这一支由 `tui_unavailable_reason` 的表驱动单测覆盖，pty 端到端覆盖 `TERM=dumb` 与过小终端两种降级。
  9. **TUI 里成功的 `/new` `/resume` `/kernel` `/model` `/details` `/memory` `/tasks` `/skills` `/status` `/context` `/help` 全部走 `slash::dispatch`**，输出行进滚动区；只有 `/sessions`（选择器）、`/compact`、`/learn`（忙碌子循环）与 `/exit` 由 TUI 侧特判——这是「不新增命令、不复制命令逻辑」的落法。
  10. **忙碌期不重建帧以外的任何东西**：捕获每 tick 排空、半行留在滚动区、任务结束时 `flush_pending()`；`facts` 在每个动作执行完与每轮任务结束后各刷一次（`refresh_facts`），忙碌期读的都是启动前那份快照。
- **任务间的名字与签名已在各任务的 Interfaces/Produces 中固定**；本计划不含大段代码正文，机制性算法（帧协议、净化白名单、截断口径、滚动区分页）只写契约与断言。
