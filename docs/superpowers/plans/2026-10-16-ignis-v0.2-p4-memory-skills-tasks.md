# Ignis v0.2 阶段四（P4）：记忆·技能·任务收口 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 把技能面与任务面收口成「看得见、改了立刻生效、记录可追溯」：`/skills reload` 重扫 `~/.ignis/skills` + 内置技能并替换会话内的目录快照；`tasks.skills_used` 出现在 `task list` 的新 `SKILLS` 列与 `task show` 的 `skills:` 头行；新增实验性 `/learn [task-id]`（读任务 JSONL + 任务行 → 一次无工具 native 请求 → 校验过的 SKILL.md 草稿 → 预览 → `[s]ave [d]iscard` → 落盘 + reload）；补 `remember` 确认行（`  ✓ memory: {key} ({scope}) {text}`）的回归面（成功必须打、失败不许打）。

**架构：** 三层落地，依赖方向不变（`cli → core → {runtime, storage}`）：

1. `apps/cli/src/commands/mod.rs` 的 `Session`：技能目录从「构造时快照」变成 `Mutex<Arc<SkillCatalog>>`——`skills()` 给出本轮快照的 `Arc` 克隆，`reload_skills()` 重扫并换掉它；`run_task` 每轮在装配 `TaskRunner` 时取一次快照，**运行中的轮次不受 reload 影响**。
2. `packages/core/src/learn/mod.rs`（新）：`/learn` 的纯逻辑面——任务行 + JSONL → 转录文本、钉死的英文 system 提示、草稿校验（frontmatter + 名字形态 + 正文非空）、`SKILL.md` 渲染与 0600 落盘（同名/已存在一律拒绝）。无工具请求的骨架与 `/compact` 共用：`session` 里抽出 `run_tool_less`（`ToolLessExecutor` 仍是私有执行器），`summarize_turns` 保留签名改为它的一层映射。
3. `apps/cli`：`slash` 加 `/skills reload` 的参数面与 `/learn` 命令（`Dispatch::{Lines, Compact, Learn}`）；新模块 `commands/learn.rs` 只管确认面的纯函数（预览截断、答案解析、提示词）；`Session::learn` 把「生成草稿」「落盘 + reload」拆成两个可单测的私有步骤，`/learn` 期间的 Ctrl-C 与 `/compact` 同款。

生成的草稿**永不自动部署、永不自动执行**（设计 §2.2 非目标：技能自我改进闭环留 v0.3）；`/learn` 只写 `~/.ignis/skills/{name}/SKILL.md` 一个文件，且必须先经用户在终端上按 `s`。

**技术栈：** Rust（edition 2024）；**零新增依赖**（草稿解析复用 `ignis_core::skills::frontmatter`；0600 用已有的 `std::os::unix::fs::OpenOptionsExt`，与 `config.rs` / `memory/mirror.rs` 同一手法）；确认读 stdin 用 `tokio::task::spawn_blocking` + `crate::input::lossy_lines`（与 `approval.rs` 同一手法）。

**Spec：** `docs/superpowers/specs/2026-10-16-ignis-v0.2-design.md`（重点 §6.9 记忆·技能·学习、§6.5 命令分组、§6.8 可观察性与 `skills_used`、§7 的 P4 行、§4 决策 #22/#23/#24、§2.2 非目标、§10 风险 3/4/7）。本计划只覆盖 P4；TUI（P5）、终端矩阵 / README / 版本号 0.2.0（P6）**不实现、也不在 `/help` 里出现**。

## 全局约束

来自设计 §3 与控制器决策，适用于本计划所有任务：

- **零新增依赖**：不添加任何 crate（含 dev-dependencies）。草稿 frontmatter 用既有的手写解析器，确认面用既有 tokio/`crate::input`，文件权限用既有 unix 扩展。
- **语言**：代码注释与文档中文；**本期新增的界面文案（`/skills reload`、`/learn`、`task show` 的 `skills:` 头、`SKILLS` 列头）一律英文**；**复用**的既有文案一个字节不改（`/memory` 的中文回执、`/kernel` 的中文错误、`✗`/`✓` 工具行、`● Done` 结束行、P3 的 `compact: …` 与 `reloaded`/`resumed` 形状）。core 的 `learn` 错误文案英文（与 `SessionError` 的 `compact:` 前缀同一先例），REPL 统一加 `error: ` 前缀。
- **命令面不动既有契约**：`COMMANDS` 的条目顺序、分组顺序（`SESSION` → `AGENT` → `INTELLIGENCE` → `INTERFACE`）与既有条目的描述不动；`/skills` 只加参数提示与描述，`/learn` 追加在 `INTELLIGENCE` 组尾。未知斜杠命令仍本地报错、不送模型（P2 行为不变）。
- **`/skills reload` 与 `/learn` 的落盘把生成内容当不可信输入**：草稿先校验再预览，用户按 `s` 才写；同名（文件已存在**或**目录里同名技能在册）一律拒绝，一个字节都不写；生成的正文永不自动执行。
- **不 Delta 既有语义**：`finish_task` 的九参签名与调用点、`render_table`/`format_time`/`short_id`/`is_id_prefix`/`CANDIDATES` 的行为、P1 渲染契约（`RendererOptions`、`resolve_color`、`format_task_end`）、P3 的会话与压缩语义（`SessionStore`、`compact_lines`、`EARLIER_SUMMARY_PREFIX`）一行不改；`ignis run` 仍是一锤子买卖。
- **测试 hermetic**：不碰真实 `~/.ignis`（单测传临时 home、pty 用例用临时 `IGNIS_HOME`）；不依赖网络与真实模型——需要模型往返的用例（`/learn`）把 config 的 `model.base_url` 指到 `ScriptedModel`。
- **生产路径无 panic、错误对人话**；锁中毒、日志缺失、坏 JSONL 行都按 fail-soft 收束（取回内部值 / 当空 / 跳过），不把用户卡在不可能完成的路径上。
- **收口验证**：每个任务收口跑 `cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`，全绿、零警告。
- **提交**：Conventional Commits，英文 type/scope + 中文正文；一次提交一个可验证单元。

## Review Focus

以下五类情形设计文档未逐条展开、但真实用户会撞上；每条都已绑定到具体任务的测试，执行者必须让这些测试存在且通过：

1. **`/skills reload` 的快照边界与覆盖语义**：reload 只影响后续轮次（运行中的 `TaskRunner` 仍持旧快照）；重扫不能翻掉「同名 user 覆盖 builtin」的既有约定，也不能让坏技能把目录整体搞丢（只记警告）。测试在 Task 1（`skills_reload_picks_up_a_new_skill_file`：`Arc::ptr_eq` 前后不同、旧快照仍是 3 条、新目录 4 条；`skills_reload_rejects_unknown_arguments`）与 Task 5（pty：写文件 → `/skills reload` → `/skills` 列出）。
2. **`skills_used` 展示面的空值与表格重排**：空表写的是 NULL，展示必须是 `-` 而不是空串；`task show` 空时整行不出现（不是 `skills: -`）；新列不许打乱既有五列的列宽、顺序与行尾不留空格的口径。测试在 Task 2（`task_list_shows_short_id_and_truncates_prompt`、`task_show_carries_the_skills_line_when_present`、`task_show_output_contains_status_and_events`）与 `slash` 的 `tasks_lines_are_the_table_plus_hint`。
3. **`/learn` 的草稿校验与落盘安全**：非法草稿（缺 frontmatter / 名字形态不合 / 正文为空）必须报 `invalid draft (…)` 且**什么都不写**；已存在的技能必须拒绝而不是覆盖；目录按需创建、文件 0600；模型失败或用户放弃时磁盘上不留任何痕迹。测试在 Task 3（`parse_draft_…`、`save_skill_creates_the_directory_and_writes_0600`、`save_skill_refuses_an_existing_file_or_a_catalog_name`）与 Task 4（`learn_saves_the_draft_and_reloads_the_catalog`、`learn_reports_an_invalid_draft_without_writing`）。
4. **确认面的输入语义与预览截断**：EOF、空行、`d`、别的输入都必须是**放弃**（只有 `s` 保存）；预览被截断时末行是 `… [truncated]`，长中文按字符切不 panic；预览与提示词必须在读之前打出来（pty 里能看见）。测试在 Task 4（`preview_lines_…`、`answer_from_lines_…`）与 Task 5（pty：预览 + `[s]ave [d]iscard>` 提示 → `s` → 落盘；`d` → `discarded` 且没有文件）。

  1. **`/skills` 的帮助条目带参数提示**：`arg_hint: "[reload]"`、`expects_args: true`（与 `/model [name]`、`/tasks [N]` 同一先例，设计 §6.5 也写作 `/skills [reload]`）。副作用：AGENT 组列宽从 13 变 16，既有 `help_lines_lists_every_command_in_its_group` 的 AGENT 四行断言按 Interfaces 的逐字数组重写（其它组不动）。

  5. **`/learn` 的默认目标需要一条 DAO**：`Db::latest_successful_task_for_workspace`（`status = 'success'` + 本工作区 + 最近一条）。用「拉 N 条再过滤」会在别的任务更密的工作区漏掉目标，故新增这一个方法，测试写在 `tasks.rs` 内联。
  6. **显式 id 的状态判定**：前缀规则（≥8 字符、`[0-9a-f-]`、0/1/多命中）复用 `task::find_task`；命中成败之外的任何状态（`aborted` / `failed` / `running` / `limit_reached`）都是 `learn: no completed task to learn from`（不是 `task not found`）。
  7. **草稿校验的失败原因逐字四种**：`missing or invalid frontmatter`（解析器不给 name/description，含空串）/ `invalid skill name: {name}` / `description is empty` / `body is empty`；模型正文全空白单独走 `empty draft`。
  8. **容错一层代码围栏**：模型把整段包在 ` ``` ` / ` ```markdown ` 里时剥掉首尾围栏行再解析（提示词明写「不要围栏」，这里是宽入严出）；不闭合的围栏按原样解析并按非法草稿报错。
  9. **确认面的形状**：`Session::learn` = `draft_for_learn`（可单测）+ 预览与确认（`commands/learn.rs` 的纯函数 + `confirm_save`）+ `commit_draft`（可单测）；预览与提示词在**读之前**打到 stdout（与 `approval.rs` 的 `InteractiveApproval` 同一写序），EOF / 读取失败 / 非 `s` 一律放弃。
  10. **落盘拒绝的两种来源合成一条文案**：目标文件已存在，或目录里已有同名技能（含 builtin）→ `Exists(name)` → `error: skill {name} already exists`，一个字节都不写（不会静默覆盖内置或用户技能）。
  11. **`/learn` 不落任务行、不动会话**：草稿请求不是任务（`tasks` 表、JSONL、`history` 都不变）；唯一的状态变化是保存成功后技能目录 reload，因此下一轮系统提示立即带上新技能。
  12. **无工具请求的骨架与 `/compact` 共用**：`session::run_tool_less`（`pub(crate)`）+ 私有的 `ToolLessExecutor`；`summarize_turns` 签名与文案一字不改，既有四条用例原样通过——两处请求的 system 提示与错误前缀各自一份（`COMPACT_SYSTEM_PROMPT` / `LEARN_SYSTEM_PROMPT`，`SessionError::Summarize` / `LearnError::Generate`）。
  13. **`remember` 的「被拒」路径**：`remember` 是 Safe 元工具，交互审批永远问不到它，e2e 里造不出「被拒绝的 remember」；回归面因此落在渲染器边界——`ok = false`（工具自身失败，如非法 scope）时一行都不打，成功时恰好一行。e2e 的两条用例（成功 / 失败）与 `render/mod.rs` 的失败用例三处合起来钉住决策 #22。
  14. **任务摘要文本的脱敏**：草稿请求读的是已脱敏的任务行与 JSONL；返回的草稿再过一遍会话脱敏器后才预览与落盘，预览与文件因此是同一份文本（C1 口径）。
